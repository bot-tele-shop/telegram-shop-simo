OPEN-SOURCE FOUNDATION AND REVIEW RECORD

This application uses aiogram 3.31.0 as a dependency, not a fork of either shop
repository below. No code from the two shop candidates is included in this app.
The inspected checkouts remain separately under the workspace references folder.

PAYMENT DOCUMENTATION
https://core.telegram.org/bots/payments-stars
https://core.telegram.org/bots/features#creating-a-bot-in-the-test-environment
Digital goods sold inside Telegram require Stars (XTR). The app sends one invoice
price, uses an empty provider token, validates pre-checkout, and delivers only
after successful_payment. Telegram test and production are separate environments.

CANBOSO INTEGRATION
Public contract reviewed: Buyer API 2.1.0 (OpenAPI 3.0.3).
https://canboso.com/api/swagger/
https://canboso.com/api/swagger/swagger-ui-init.js
Uses documented products and balance GETs and purchase POST only. GET buyer-key
query parameters and POST JSON key plus Idempotency-Key follow that contract.
No supplier order-status, refund, or sandbox endpoint was documented. Pending
seller fulfillment requires manual verification. Uncertain purchases never trigger
an automatic POST retry. The provider does not document a maximum-price parameter
or idempotency retention duration; local checks cannot guarantee upstream prices.
Merchant-selected authorized account/slot products only; upgrade_account is not
supported. Stars are customer payments, separate from the merchant supplier wallet.
Offline mock tests are not a live supplier/payment integration certification.
