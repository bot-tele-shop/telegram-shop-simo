What the bot can do

  • Browse paginated products; buy one product per Stars invoice.
  • Record agreement to versioned terms and a privacy notice.
  • Reserve stock at checkout and allocate one item per paid order.
  • Deliver a private text key or download link; let the buyer reopen delivery through /orders.
  • Import stock locally or through admin-only .txt uploads.
  • Retry failed deliveries using the same allocated item.
  • Request and confirm full Stars refunds; quarantine refunded stock.
  • Persist incoming updates before advancing Telegram’s polling offset.

Not connected yet

The supplier API.

The first version delivers inventory you import. A supplier adapter interface is present but deliberately disabled: no guessed endpoints, no account automation, no supplier purchases.

Next: provide the API docs, authentication method, product catalog and order-status examples. Keys belong in local configuration, not in chat.

Operational limits

Run one bot process on a persistent disk. SQLite is not a multi-host deployment. A network timeout can cause the same delivery message to be resent; it does not allocate a second key.

Full production reconciliation, automatic supplier ordering, attachment hosting, automated key revocation, and a web-admin panel are not implemented. Backups, monitoring and Telegram test-environment validation are launch prerequisites.

Local project handover

Connect your bot when you’re ready.

The source archive includes the bot, tests, sample catalog, configuration example and third-party notices. It excludes tokens, encryption keys, runtime databases and cloned reference repositories.

This is the bundled preview. The application source is one folder above.

If your preview blocks downloads, use the ZIP file card in the conversation.

1Open the project and install dependencies

Use Python 3.11–3.14 and a virtual environment. Run these from the extracted project folder. On this computer, an isolated environment is already installed.

python -m venv .venv
# Windows PowerShell:
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m shop demo
# macOS / Linux: use .venv/bin/python instead.

2Create local configuration

.venv\Scripts\python.exe -m shop init
.venv\Scripts\python.exe -m shop seed-demo

init creates config.local.json with a unique encryption key and sales disabled. It refuses to overwrite an existing configuration. Keep this file private and back it up securely; losing the key makes inventory unreadable.

3Complete your merchant settings

Set your bot token, numeric admin IDs, support contact, real terms and privacy notice locally. The bot also accepts BOT_TOKEN, ADMIN_IDS and STOCK_ENCRYPTION_KEY environment variables. Never publish these.

bot_token: your own bot token
admin_ids: numeric Telegram IDs, not usernames
support_contact: a working merchant contact
terms_text: your terms, delivery and refund policy
privacy_text: data you store, purpose and retention
environment: test
enable_sales: false until configuration is ready

Test mode needs a bot created in Telegram’s separate test environment. A normal BotFather token is not a test-server token. Keep separate databases and bots for testing and production.

Official test-environment instructions

4Check, then run

.venv\Scripts\python.exe -m shop doctor
.venv\Scripts\python.exe -m shop run

Set enable_sales to true in your test configuration to exercise checkout. The bot uses polling, so it needs outbound internet but no public web server. It refuses to remove an existing webhook automatically.

5Add your own licensed products

Use sample/catalog.json as a structure reference. Create your own entries with is_demo: false, integer Stars prices and a unique SKU. Inventory goes in a private UTF-8 text file: one unique code or download link per line.

.venv\Scripts\python.exe -m shop import-catalog catalog.json
.venv\Scripts\python.exe -m shop stock --sku your-sku --file stock.private.txt

Remote product files are not hosted or access-controlled by this MVP. Supply valid private links and honor their licensing and refund terms.

Before going live

1Complete end-to-end tests on Telegram’s test server.
2Use a production bot, fresh production database and encryption key.
3Import only real products you own or may resell.
4Set environment to production and production_acknowledged to true.
5Configure support, backups, monitoring and your applicable merchant obligations.
6Explicitly enable sales after checking the catalog.
Digital goods sold inside Telegram must use Telegram Stars (XTR). Crypto and card checkout are intentionally not included.
